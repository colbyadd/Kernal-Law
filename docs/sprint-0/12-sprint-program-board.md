## Sprint Scope and Definition of Done

### S0: Baseline and Control Plane

Deliverables:
1. 10/10 rubric documented.
2. URL baseline scorecard completed for top commercial pages.
3. Prioritized sprint board with dates and exit gates.
4. Standards updated for pillar/subpillar uniqueness and UX consistency.

Done when:
- Baseline docs are approved.
- Top-20 URL priority order is locked.

### S1: UX Foundation

Deliverables:
1. Header/navigation and IA consistency pass across desktop/mobile.
2. Standardized above-the-fold composition and CTA hierarchy.
3. Page-level scannability pattern pass (headings, section rhythm, trust-first sequencing).

Done when:
- UX score on core pages (`/`, `/criminal-defense`, `/personal-injury`, `/contact`) is `>= 8.0`.

### S2: Template and Standards Enforcement

Deliverables:
1. Enforce one canonical structure for pillar/service/market pages.
2. Add uniqueness checklist and QA gate per market subpillar.
3. Add editorial QA checklist for proof, legal safety, and local depth.

Done when:
- New/updated pages cannot ship without checklist pass.

### S3: Criminal Pillar Rebuild

Deliverables:
1. Rebuild `/criminal-defense` to authority depth.
2. Rebuild top criminal service pages (`dui-dwi`, `drug-charges`, `warrants`, plus highest-value additional pages).
3. Add stronger trust modules and structured internal linking.

Done when:
- Criminal top pages average `Content >= 8.0`.

### S4: Injury Pillar Rebuild

Deliverables:
1. Rebuild `/personal-injury` to authority depth.
2. Rebuild top injury service pages (`car-accidents`, `truck-accidents`, `wrongful-death`, plus highest-value additional pages).
3. Add damages/process/evidence depth and conversion framing.

Done when:
- Injury top pages average `Content >= 8.0`.

### S5: Proof and Trust Stack

Deliverables:
1. Redesign case-results information architecture (taxonomy + scannable proof).
2. Redesign reviews architecture and integrate trust blocks into money pages.
3. Strengthen attorney authority page and proof distribution pattern.

Done when:
- `/case-results` and `/client-reviews` reach `UX >= 8.0` and `Content >= 7.5`.

### S6: Market Wave 1 (Top Cities)

Deliverables:
1. Rebuild high-value city subpillars first (`oklahoma-city`, `norman`, `edmond`, `moore`, `midwest-city`).
2. Add materially unique local legal context per page.
3. Normalize internal links from market pages to relevant service/resource pages.

Done when:
- Wave-1 city pages average `Content >= 8.2`.

### S7: Market Wave 2 (Counties + Secondary Cities)

Deliverables:
1. Rebuild county-first pages (`oklahoma-county`, `cleveland-county`, `canadian-county`, `payne-county`, others).
2. Rebuild secondary city pages from same standard.
3. Eliminate near-duplicate local blocks.

Done when:
- County/secondary market pages average `Content >= 8.0`.

### S8: Resource Authority Engine

Deliverables:
1. Expand resource hub architecture and taxonomy.
2. Publish high-value legal guides mapped to conversion intent.
3. Build tighter bidirectional links between resources and money pages.

Done when:
- Resource-assisted internal click-through to money pages increases sprint-over-sprint.

### S9: Technical SEO Hardening

Deliverables:
1. Schema QA pass across priority pages.
2. Internal-link and cannibalization cleanup.
3. Metadata/canonical consistency pass and sitemap quality check.

Done when:
- No critical technical blockers remain on priority set.

### S10: CRO and Intake Optimization

Deliverables:
1. Run controlled CTA/form experiments on top pages.
2. Reduce form friction and improve conversion confidence copy.
3. Improve contact-path performance on mobile.

Done when:
- Contact conversion metrics improve without lead-quality decline.

### S11: Final Optimization and SOP Handoff

Deliverables:
1. Prune/merge weak pages and tighten cluster architecture.
2. Final scoring pass across top-20 pages.
3. Publish ongoing operations SOP (weekly scoring, monthly refresh, quarterly audits).

Done when:
- Top-20 pages average `Content >= 9.0` and `UX >= 9.0`.

## Operating Cadence

Weekly:
1. Re-score top 20 URLs.
2. Review UX friction and conversion-path issues.
3. Approve sprint backlog changes.

Biweekly (sprint close):
1. Ship review against exit criteria.
2. Risks/dependencies update.
3. Next sprint lock.

Monthly:
1. Market coverage quality audit.
2. Resource-to-conversion pathway audit.
3. Proof/trust module freshness review.
